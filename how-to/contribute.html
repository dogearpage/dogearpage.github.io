Make pull requests

Found a bug, want a new theme or have an idea? Here's how to send it in.

This page is about changing the site itself for everyone. To change your own links or look, you don't need GitHub at all; see How to use and Personalize.

Before you start

  • You need a free GitHub account.
  • For anything bigger than a small fix, open an issue first describing what you'd like to change. It saves you work if the idea needs adjusting.
  • Just reporting a problem? An issue on its own is perfect. Say what you did, what you expected and what happened, and which browser you used.

Option A: entirely on github.com (easiest)

Good for text fixes, a new theme color or other small, single-file changes.

  1. Open the file you want to change in the repository, for example index.html.
  2. Click the pencil Edit this file button. GitHub offers to fork the repository (make your own copy); accept.
  3. Make your change in the editor.
  4. Click Commit changes…, write a short message that says what changed (e.g. "Add Spring theme"), then Propose changes.
  5. On the next screen, click Create pull request. Describe what you changed and why, and add a screenshot if it changes how the page looks. Submit it.

Option B: on your computer with Git

Better for bigger changes, several files, or when you want to try things in your browser before sending them.

  1. On GitHub, click Fork on the repository page.
  2. Clone your fork and create a branch for your change: 
    git clone https://github.com/YOUR-USERNAME/dogearpage.github.io.git
cd dogearpage.github.io
git checkout -b add-spring-theme
  3. Edit the files, then open index.html straight in your browser to test (double-click it; there's no build step or server needed). Check both pages and a light and dark theme.
  4. Commit and push: 
    git add .
git commit -m "Add Spring theme"
git push -u origin add-spring-theme
  5. Back on GitHub, your fork shows a Compare & pull request banner. Click it, describe the change and submit.

If the original repository moves on while you're working, bring your branch up to date with GitHub's Sync fork button, or from the command line: 

git remote add upstream https://github.com/dogearpage/dogearpage.github.io.git
git fetch upstream
git rebase upstream/main

Guidelines that get pull requests merged

  • One change per pull request. A new theme and a bug fix are two pull requests.
  • Keep the pages self-contained. index.html and acronyms.html each carry their own styles and script on purpose, with no build tools or frameworks. Please keep it that way.
  • Keep everything in the browser. The site never sends people's links anywhere. Changes that add tracking, accounts or a server won't be accepted.
  • Themes and fonts live in several places. They're copied in index.html, acronyms.html, how-to/howto.css and how-to/howto.js. If you add or change one, update all of them.
  • Don't break saved data. People's links are stored under the keys nm_data, nm_settings and acronyms. If you change the shape of that data, make the page still read what's already saved.
  • Explain the why. Match the existing style: comments that explain why code does something, and a short doc comment on each function.
  • Show it. For visual changes, include before and after screenshots in the pull request.

After you submit

The maintainer reviews it and may ask questions or suggest changes; push more commits to the same branch and the pull request updates itself. Once it's merged, GitHub Pages republishes the site within a few minutes.
